# Organization recommendation report

Mode Read, inside the established BinaHub diagnosis world. The user explicitly
requests a consulting-style dashboard, not an unrelated identity. Client on a
laptop/phone in a normal office needs to understand the recommendation immediately.

## Direction contract
THESIS: Explain the path from stated need to competency to catalog option, never
substitute decoration, invented scores, or an unexplained consultation placeholder.
OWN-WORLD: Existing navy, white, cool slate ground, inherited sans; thin rules,
compact readable type and restrained blue information surfaces, no new brand.
STORY: Understand the need and review status; inspect evidence-linked program
options, scope/investment and the next discussion; expand background only as needed.
FIRST VIEWPORT: Navy report masthead; three-column need/impact/outcome diagram;
honest recommendation status; program section immediately follows. Sidebar-free
on mobile. Next action is consultation/email after the proposal details.
FORM: Brief-pinned dashboard with semantic sections and native details, code-led.
seed: none (brief-pinned)
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Public and admin reuse the same renderer; PDF uses the same immutable report.
Do not invent competency test scores, prices, urgency, timestamps or program fit.
